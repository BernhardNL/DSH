# dsh-math-assistant — 数学建模助手（DSH 插件）

一个运行在 **DeepSeek Harness（DSH）** Web 界面里的数学建模助手：从读题、分析、建模、算数据、写代码，到一键生成规范 Word 论文，全程在一个独立页面里完成，并保留按项目隔离的记忆。

- 独立页面：`http://<host>:<port>/math-assistant`
- 六区块：题目分析 / 需求与提问 / 阶段显示 / 文献参考 / 程序 / 数据
- 一键 Word 论文：公式 LaTeX → **Word 原生公式**，统计图自动嵌入
- 记忆按项目隔离，重启保留，清除需确认

---

## 一、别人电脑上怎么装（三步）

前提：目标机器已安装并运行过 DSH（`dsh web` 至少启动过一次，`web` profile 已初始化）。

### 第 1 步：拿到插件目录

把整个 `dsh-math-assistant` 目录复制/分发到目标机器任意位置（例如 `~/dsh-math-assistant`）。目录里需要包含：`package.json`、`lib/`、`scripts/`、`src/`、`README.md`。**不需要** `node_modules/`（见第 2 步），**不需要** `.venv/`（见第 3 步）。

### 第 2 步：安装依赖并构建

```bash
cd ~/dsh-math-assistant
npm install                       # 构建依赖（typescript/esbuild/@deepseek-ai 类型包/marked/katex）
npm run build                     # 生成 lib/（服务端 + 客户端 bundle）
```

### 第 3 步：创建 Python 环境（建模/数据处理/论文转换都需要）

```bash
python3 -m venv .venv
.venv/bin/pip install pypandoc-binary pandas numpy scipy sympy matplotlib python-docx latex2mathml mathml2omml
```

> `pypandoc-binary` 自带 pandoc 二进制（负责 LaTeX 公式 → Word 原生公式），无需单独装 pandoc。
> `latex2mathml` + `mathml2omml` 是 docx 原位补公式的主转换器（对 `\text`、`\mathbb` 等支持更稳；pandoc 仅作兜底）。
> 解析问题 PDF 需要系统 `pdftotext`：
> - Ubuntu/Debian：`sudo apt install poppler-utils`
> - macOS：`brew install poppler`
> 如果只需要 txt/文档描述题目、不传 PDF，可跳过。

### 第 4 步：链接进 DSH 并注册

```bash
ln -sfn ~/dsh-math-assistant ~/.dsh/profiles/node_modules/dsh-math-assistant
```

编辑 `~/.dsh/profiles/web/cordis.patch.yml`，追加（**`pythonPath` 换成你机器上的实际路径**）：

```yaml
- insert:
    - id: math-assistant
      name: 'dsh-math-assistant'
      config:
        enabled: true
        pythonPath: '/home/你的用户名/dsh-math-assistant/.venv/bin/python'
```

重启：

```bash
dsh web
```

侧边栏底部会出现 🧮 按钮，点击打开数学建模助手。

## 二、怎么用

### 0. 工作区

点开页面后，先选**工作区/会话**（下拉框）。该会话的工作目录就是你的**建模项目文件夹**——所有产物（代码、数据结果、论文、记忆）都放在这里。建议每个建模题建一个独立文件夹。

### 1. 题目分析

- 在"题目分析"区输入题目描述，或从"工作区文件"下拉选择问题文件（把 PDF/docx/txt 放进工作区文件夹即可），点"设定题目并分析"。
- 助手会对每一问输出：**问题类型 / 候选模型 / 算法 / 工具 / 解决思路 / 子问题拆分**。

### 2. 需求与提问

- 上半输入、下半回答。
- **普通提问**：直接问，如"问题一该用什么模型？"；问题里引用工作区文件路径（如 `论文.docx`）会自动读取内容供助手分析
- **建模命令**：以"求解/建模/分析/实现/建立/拟合/预测/优化/模拟/整理"等开头的输入会自动进入**流水线**，自动规划步骤并执行（会反映到"阶段显示"）。

### 3. 阶段显示

命令执行时自动生成总体步骤设计，逐阶段执行并显示：当前阶段、状态（待执行/执行中/完成/失败）、推理简述、阶段输出（可展开）。

### 4. 文献参考

输入主题（如"ARIMA 时间序列预测"）点"收集"，返回参考文献列表+链接。**链接可达性已校验，但内容是否真实支撑建模请人工抽查**（模型可能给出看似合理但不存在的引用，未通过校验的会标注"⚠️ 未验证"）。

### 5. 程序

输入实现要求（如"用 scipy 求解第一问的线性规划"）点"生成代码"：
- 生成 python 代码（注释写"为什么"而不是"是什么"）；
- **语法校验**通过后**弹窗确认**是否写入工作区；
- 确认后写入 `工作区/code/*.py`。

### 6. 数据

把数据文件（txt/csv/xlsx）放进工作区，选择文件（可选填"显示要求"，如"显示每个区域的平均值和高峰时段"）点"处理数据"。结果展示行数/列/类型/缺失/统计描述，以及你指定的分析结果。

### 7. 一键 Word 论文

点"生成/修改论文"：
- 从项目记忆（题目+分析+数据+流水线输出）自动汇编标准结构论文（摘要/关键词/问题重述/模型假设/符号说明/模型建立与求解/检验/模型评价/参考文献）；
- 公式以 LaTeX 书写，转换后成为 **Word 原生公式**（可编辑），统计图自动嵌入；
- 输出 `工作区/论文/论文_时间戳.docx` + Markdown 底稿；
- 在输入框填写修改要求再点按钮，可对论文进行修改重新生成。

### 8. 记忆

"项目记忆"区可查看状态；**清除记忆**会弹窗确认，确认后才清除（题目/分析/数据/流水线/文献/代码/论文/聊天全部清空）。

## 三、命令一览（在需求与提问里输入）

| 命令 | 作用 |
|---|---|
| `/math-problem <描述或文件名>` | 设定题目并自动分析 |
| `/math-analyze` | 重新生成题目分析 |
| `/math-ask <问题>` | 普通提问 |
| `/math-run <命令>` | 建模命令 → 流水线 |
| `/math-code <要求>` | 生成代码（验证+确认写入） |
| `/math-data <文件> [显示要求]` | 处理数据 |
| `/math-refs [主题]` | 收集文献 |
| `/math-paper [修改要求]` | 生成/修改 Word 论文。**若项目已把源论文设为问题文件（docx/pdf），会自动转为重排版**（保留全文、补公式），而不是从记忆新写压缩草稿 |
| `/math-repaper <源论文> [要求]` | 读取已有论文（docx/pdf/txt），通读并**逐处补充缺失公式**（【待展开】等占位 → 完整 LaTeX）。**docx 源采用原位修补：保留全部公式/表格/图片/排版，只在占位符处插入 Word 原生公式**（不做"抽取文本→重建"，绝不丢内容）；pdf/txt 源走文本管线，要求里加"按格式重排"会套用已学格式规范 |
| `/math-learn-format <参考论文...>` | 从严谨格式的参考论文**学习格式规范档案**（章节/标题/公式编号/图表/引用等），之后重排版/生成论文可套用 |
| `/math-format [status\|clear]` | 查看/清除已学习的格式规范 |
| `/math-memory [status\|clear]` | 记忆状态 / 清除（确认） |
| `/math-files` | 列出工作区文件 |
| `/math-status` / `/math-snapshot` | 流水线状态 / 记忆快照（页面内部用） |

## 四、配置项（`cordis.patch.yml` 中 `math-assistant` 行的 config）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `pythonPath` | 插件目录 `.venv` 自动探测（**通过加载器时可能失效，建议显式配置**） | Python 解释器路径（含 pandas 等科学库与 pypandoc 的 venv） |
| `workDir` | `.harness/math` | 项目内工作目录（临时脚本等） |
| `paperDir` | `论文` | 论文输出目录（相对项目根） |
| `llm.temperature` / `llm.maxTokens` | `0.3` / `3000` | 建模 LLM 调用参数 |

## 五、常见问题

**1. 打开页面后"工作区"下拉是空的？**
页面会话列表来自 DSH 会话。先在主界面新建/选择一个会话（其工作目录即建模项目文件夹），再打开助手页面；或直接在助手页面刷新后从下拉选择。

**2. 数据处理报错 / 显示 0 行？**
`pythonPath` 没生效。确认 `cordis.patch.yml` 里的 `pythonPath` 指向真实的 `.venv/bin/python`，且 `.venv` 里装了 pandas。

**3. 生成论文提示"Word 转换失败"？**
`.venv` 里没有 `pypandoc-binary`（或安装失败）。重跑：`.venv/bin/pip install pypandoc-binary`。论文 Markdown 底稿仍会生成在 `论文/`。

**4. 流水线某个阶段输出为空？**
DSH 底层模型偶发空响应。插件已内置 3 次自动重试；仍为空会给出占位提示，可换一种表述重跑命令。

**5. 无法解析问题 PDF？**
系统未装 `pdftotext`（见安装第 3 步），或 PDF 是扫描图片（无文字层）。

**6. 想完全卸载？**
删除 `cordis.patch.yml` 中的注册行 → 删除软链 → 重启 `dsh web`；再删插件目录与工作区里的 `.harness/math/`。

## 六、诚实说明（局限）

- **数学正确性**：标准模型（回归/规划/时间序列等）组合运用可靠；复杂长链推导仍可能出错，建议在提问里让助手用 sympy/数值验证自检，**最终结论请人工核查**。
- **文献真实性**：可能生成虚假引用，链接已校验，内容请抽查。
- **统计图**：保存在 `.harness/math/figures/` 供论文嵌入；页面内暂不直接预览图片。
- **论文质量**：模板与结构严格，但"好不好"仍需要你自己把关；对已生成论文可反复提修改要求。
- **重排版（/math-repaper）**：公式补全采用"插件定位占位符 + 模型逐处生成 LaTeX + pandoc 转 Word 原生公式"；自动补的公式是草稿，**请人工核对数学正确性**后再定稿。**docx 源为原位修补**：直接在原文件上把占位符换成 OMML 公式，原有公式、表格、图片、目录、样式全部保留，绝不重建文档（重建会丢失这些结构）；论文里没有【待展开】等占位符时，重排版不再中断，会照常输出（原样复制）全文 Word。
- **模型偶发空响应**：底层 LLM 偶尔对长输出返回空，插件已内置 3 次重试（自动提高输出预算）+ 短输出任务拆分（重排版逐处请求）；仍遇空可重试或换表述。
- **格式学习**：`/math-learn-format` 从参考论文提炼格式档案（按项目隔离持久化）；重排版时只有要求里含"按格式重排"才做逐块重排（全文逐块重排（不限块数），中途可取消，排后自动自检，避免长时间运行）。
- **重排保真防护**：逐块重排要求"只改排版、逐字保留内容"；某块输出不足原文 70% 判定为被截断/压缩，自动保留原文并在自检报告里警告；全文整体缩水 <60% 也会给出强警告，避免"排完只剩一小截"。

## 七、给分发者（可选）

当前 `package.json` 为 `private`。若要发布到 npm 方便别人一行安装：

1. 去掉 `private`，改包名（如 `@你的名字/dsh-math-assistant`）；
2. `npm publish`；
3. 别人装完 `npm install` 构建后，用 `dsh plugin --profile web add <包名>` 或软链方式注册（仍需手动配置 `pythonPath` 与创建 `.venv`）。
